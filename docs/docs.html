Losna CLI Documentation & Manual

Complete guide to installing, configuring, securing, and extending your terminal AI auditing companion.

1. Quickstart & Installation

Losna CLI installs in a completely isolated environment inside ~/.losna/. No system Python packages are overwritten or modified.

Prerequisites:
  • Git installed and in system PATH
  • Python 3.10 or newer (tested up to Python 3.13)
Windows (PowerShell):
irm https://raw.githubusercontent.com/snui1s/losna-cli/main/install.ps1 | iex
macOS / Linux (Bash):
curl -sSL https://raw.githubusercontent.com/snui1s/losna-cli/main/install.sh | bash

After the script finishes, restart your terminal and run losna to start.

2. API Configuration (BYOK)

On first launch, Losna CLI prompts you to save your API keys to ~/.losnarc.

OpenRouter API Key (Required)

Gives you access to DeepSeek V3, DeepSeek R1, Claude 3.5 Sonnet, and GPT-4o with zero token markup.

Tavily API Key (Optional)

Enables real-time web search for online CVE lookups and documentation verification.

3. Read-Only Safety Guard

When auditing sensitive or production repositories, activate Read-Only mode with /readonly.

How Safety Works at the Engine Level:
  1. Schema Filter: Modifying tools (write_to_file, replace_file_content, etc.) are omitted from the model schema entirely.
  2. Runtime Gate: Any attempt to invoke file mutation or arbitrary shell commands returns a hard runtime block.
  3. Interactive Interception: In normal mode, destructive commands pause and require a terminal (y/n) confirmation.

5. Plugin & Skill Development

Skills in Losna CLI are simple folders containing instructions in SKILL.md. You can create your own in ./skills/<skill-name>/ or install them directly from GitHub:

# Install a plugin bundle directly from GitHub:
losna > /plugin add https://github.com/snui1s/losna-plugins

# Or install a specific skill only:
losna > /plugin add https://github.com/snui1s/losna-plugins --skill security-auditor

6. SQLite Memory Architecture

All chat history, token compaction stats, and core rules are stored in a local SQLite file: agent_data.db.

Auto-Compaction

Summarizes older message turns when token count grows high, ensuring low latency.

Core Memory Pinning

/pin <fact> stores persistent facts injected into every future conversation turn.
